# agent dynamic UI design system

This is the plugin's design system. It replaces the earlier ad hoc typography rules. The purpose is readable, varied black-and-white layouts for an e-paper screen.

## Sources of truth

- `src/design/tokens.json`: typography minimums, semantic roles, ink, spacing, and prohibited treatments.
- `dist/design-system.css`: shared CSS variables generated from those tokens.
- `src/templates/v2.liquid`: six composition templates using the shared variables.
- `src/templates/v1.liquid`: legacy grid, with the same minimum text rules.
- `dist/full.liquid`: combined installed renderer, generated by `scripts/build.mjs`.
- `tests/design.mjs`: local rendering and computed typography checks.

Run `node scripts/build.mjs` after changing tokens or template sources. It regenerates the shared CSS and combined renderer. Upload the combined `dist/full.liquid` through TRMNL MCP `writeMarkup`, size `markup_full`, plugin_setting_id `522048`.

## Typography

| Role | Size | Weight | Line height |
| --- | --- | --- | --- |
| Metadata and compact labels | 16px minimum | 700 | 22px |
| Body copy | 18px default | 400 | 26px |
| Section heading | 18px default | 700 | 24px |
| Time or value | 18–130px, by composition | 700 or heavier | Composition-specific |
| Editorial headline | 27–76px, by composition | 400 serif or bold sans | Composition-specific |

No rendered text may be smaller than 16 CSS pixels. Text at 16px must have a numeric computed weight of at least 600. Large serif headings may use normal weight. These are renderer rules, not a guarantee of physical legibility: panel size, server scaling, viewing distance, and font rendering still matter. Device feedback should raise the floor if necessary.

The decorative bottom footer is retired. Do not restore a brand label, composition label, or timestamp as tiny bottom text. Necessary timestamps belong in the readable top metadata area. Do not auto-shrink text to make it fit. Shorten the content or select a less dense composition.

## Ink and spacing

Use black text on white. One inverse black region is allowed in the spotlight composition. Avoid gray text and low-contrast metadata. Use whitespace and solid rules for grouping. Repeated rounded cards are confined to the legacy v1 grid.

Use a 4px spacing unit and a 24px main inset in v2. Keep headlines, body text, and supporting information visually distinct. Layout-specific spacing may use half steps where needed for typography. Character limits are upper bounds; they do not replace rendering checks.

## Available compositions

| Layout | Component order | Purpose |
| --- | --- | --- |
| editorial | brief, metric, list | Large lead and a supporting rail |
| spotlight | metric, brief, agenda | One dominant number and supporting context |
| timeline | agenda, list | Time-led schedule with a checklist |
| scoreboard | four metrics, brief | Figures followed by an interpretation |
| focus | brief, list | One action with a definition of done |
| dispatch | brief, table, agenda | Digest with project and schedule details |

The agent selects the composition and supplies plain text JSON. It cannot select arbitrary font sizes, weights, colors, or CSS. v2 determines widths and visual emphasis from the composition. `src/schemas/v2.json` plus `src/validate-v2.mjs` define the payload contract; `src/validate.mjs` accepts both schema versions.

## Required render checks

From the repository root, run `npm ci` if dependencies are missing, then `node tests/design.mjs`. Google Chrome must be installed at the standard macOS path used by that script.

For each of the six gallery screens, the check:

1. Validates its payload.
2. Renders the actual combined installed template at 800×480 using the included TRMNL framework assets.
3. Inspects computed styles on every element with direct visible text: size must be at least 16px, and text at 16px must have weight at least 600.
4. Asserts that no `.dui-footer` exists.
5. Checks each content section for horizontal and vertical overflow.
6. Saves a PNG, portable HTML preview, and `artifacts/design/render-results.json`.

Run `npm test` for the build, legacy layouts, payload validation, and the v2 design checks. Use TRMNL `startPreview`/`getPreview` after installing changes to verify its server renderer and target device model. A local gallery check does not certify every possible payload or physical device readability; new content that wraps differently should be previewed too.

## MCP-discoverable contract

The installed Full markup begins with `AGENT_DYNAMIC_UI_CONTRACT/1` in a Liquid comment. An authorized MCP client can call `readMarkup` with `plugin_setting_id: "522048"`, `size: "markup_full"` to retrieve the minified v2 JSON Schema, composition constraints, design tokens, validation limits, legacy rules, and update/preview procedure. The comment is absent from rendered output. `scripts/build.mjs` regenerates it from the schema, tokens, and exported composition definitions; `dist/AI-CONTRACT.liquid` is the generated copy. The local render scripts are described but are not exposed as executable MCP tools.
