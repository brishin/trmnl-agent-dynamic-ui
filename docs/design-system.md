# agent dynamic UI design system

This is the plugin's design system. It replaces the earlier ad hoc typography rules. The purpose is readable, varied black-and-white layouts for an e-paper screen.

## Sources of truth

- `src/design/tokens.json`: typography minimums, semantic roles, ink and fills, spacing, and prohibited treatments.
- `src/design/weather.json`: weather conditions, their icon, severity shade, and WMO codes.
- `src/design/columns.json`: width and height budgets for `columns` blocks.
- `vendor/weather-icons/`: pinned copies of the Weather Icons SVGs the renderer loads from trmnl.com; tests serve them offline.
- `dist/design-system.css`: shared CSS variables generated from those tokens.
- `src/templates/v2.liquid`: twelve composition templates using the shared variables.
- `src/templates/v1.liquid`: legacy grid, with the same minimum text rules.
- `dist/full.liquid`: combined installed renderer, generated by `scripts/build.mjs`.
- `tests/design.mjs`: local rendering and computed typography checks.

Run `node scripts/build.mjs` after changing tokens or template sources. It regenerates the shared CSS and combined renderer. Upload the combined `dist/full.liquid` through TRMNL MCP `writeMarkup`, size `markup_full`, plugin_setting_id `522048`.

## Typography

| Role | Size | Weight | Line height |
| --- | --- | --- | --- |
| Metadata and compact labels | 16px minimum | 700 | 22px |
| Body copy | 18px default | 400 | 26px |
| Section heading | 18px default | 700 | 24px |
| Time or value | 18–130px, by composition | 700 or heavier | Composition-specific |
| Editorial headline | 27–76px, by composition | 400 serif or bold sans | Composition-specific |

No rendered text may be smaller than 16 CSS pixels. Text at 16px must have a numeric computed weight of at least 600. Large serif headings may use normal weight. These are renderer rules, not a guarantee of physical legibility: panel size, server scaling, viewing distance, and font rendering still matter. Device feedback should raise the floor if necessary.

The decorative bottom footer is retired. Do not restore a brand label, composition label, or timestamp as tiny bottom text. Necessary timestamps belong in the readable top metadata area. Do not auto-shrink text to make it fit. Shorten the content or select a less dense composition.

## Ink and spacing

Text is pure black or pure white at every size; never gray. One inverse black layout region is allowed: the spotlight hero, or the current day in a calendar component. Avoid low-contrast metadata.

Gray is allowed as a data fill. Forecast pills and range bars use the framework's `bg--gray-NN` steps (15–75), which dither on 1-bit screens. Fills at gray-55 or darker are inverse: white text with a black framework text stroke (gray-30 on 2-bit and 4-bit screens), and white icons with a black outline. Each pill or bar may be filled; the one-inverse-region rule applies to layout regions, not chart marks. Use whitespace and solid rules for grouping. Repeated rounded cards are confined to the legacy v1 grid.

Use a 4px spacing unit and a 24px main inset in v2. Keep headlines, body text, and supporting information visually distinct. Layout-specific spacing may use half steps where needed for typography. Character limits are upper bounds; they do not replace rendering checks.

| --- | --- | --- |

| outlook | forecast, brief | Weather pills on one temperature scale with an interpretation |

The agent selects the composition and supplies plain text JSON. It cannot select arbitrary font sizes, weights, colors, or CSS. v2 determines widths and visual emphasis from the composition. `src/schemas/v2.json` plus `src/validate-v2.mjs` define the payload contract; `src/validate.mjs` accepts both schema versions.

## Calendar components

Calendar blocks carry dates as plain data; the renderer never computes dates, so the agent supplies correct weekdays, day numbers, and countdowns.

| Component | Fields | Rendering |
| --- | --- | --- |
| `dates` | 1–4 items: `month` (≤4), `day` (1–2 digits), optional `weekday` (≤3), `text` (≤36), optional `until` (≤12, e.g. "In 12 days") | Calendar leaves: a large day number with month and weekday |
| `month` | `first_weekday` 1=Monday…7=Sunday, `days_in_month` 28–31, optional `today`, up to 10 `marked` day numbers | Monday-first grid; today filled, marked days circled |

Column stress cases fill every count from 2 to 8, in both `board` and `weekahead`, with the widest allowed text and parts until the height budget refuses more.

Composition limits: almanac month titles ≤18 characters and at most 3 dates; weekahead and countdown briefs ≤120 characters of text, and weekahead brief titles ≤24. `tests/design.mjs` renders each calendar composition at these maxima with wide words and checks that invalid calendars are rejected.

## Charts and weather

Both chart components draw 3–7 marks on one shared vertical scale. The scale spans every mark plus the optional `now` value, so marks show both their own range and their place in the whole. The renderer computes positions only; the agent supplies the values.

| Component | Fields | Rendering |
| --- | --- | --- |
| `forecast` | `unit` °F/°C, `mode` `range` (daily low–high) or `point` (hourly, one temperature in `low`), optional `now` {`temp`, `label` ≤10, `trend` rising/falling/steady}, 3–7 `periods`: `label` ≤6, `condition`, `low`, `high` (range only) | Rounded pills with an icon and rounded temperatures, shaded by severity |
| `range` | optional `unit` ≤4 (shown above the now column), optional `now` {`value`, `label`, `trend`}, 3–7 `bars`: `label` ≤6, `low`, `high`, optional `level` 0–3 | Floating bars with raw values; `level` darkens the fill (70/60/45/15) |

The `now` marker is a rule at the current value with a large figure, its label, and a rising or falling arrow at the end. Pills have a minimum height so their content fits; a pill near the bottom of the scale is pushed up to stay inside the plot. Forecast numbers must be at most 3 characters after rounding, and range numbers at most 4 characters as written (`14.2`, `-999`). Send whole numbers as integers so Ruby Liquid does not print `22.0`.

## Inline icons

An optional `icon` (any condition above) places a weather icon beside text. It is sized in `em`, so it follows the surrounding type. Icons are black SVG images loaded from `https://trmnl.com/images/plugins/weather/`, the URLs the Weather Glance plugin uses; on dark ground (inverse pills, a highlighted column, the spotlight hero) a CSS filter inverts them. Inlining them would push the markup past the TRMNL MCP upload limit.

| Where | Placement |
| --- | --- |
| `brief` | Before the title |
| `metric` | After the value |
| `agenda` items | Before the event text |
| `dates` items | Before the item text |
| `columns` headers | After the column value |
| `text`, `event`, `metric` parts | Before the text, or after a metric figure |
| `list` items | Give `{"text","icon"}` instead of a plain string; the icon precedes the text |

Text fields stay plain escaped strings; there is no in-string icon syntax. Icons are absent from headings and `updated_at`. An icon takes horizontal space, so long items may wrap sooner.

## Columns and parts

`columns` lays out 2–8 equal columns, each a header and a stack of up to 6 parts. A week is a columns block whose labels are weekdays, values are day numbers and highlighted column is today; the separate `week` block was retired in its favor. The agent picks part kinds and supplies plain text; it cannot set sizes, widths or styles.

| Column field | Meaning |
| --- | --- |
| `label` (required, ≤12) | Uppercase header, e.g. `WED` or `Maya` |
| `value` (≤4), `icon` | Large numeral and/or weather icon under the label |
| `highlight: true` | Inverse column; at most one |
| `align` | `top` (default), `center`, `spread` (first part at the top, last at the bottom) or `bottom` |
| `content` | 0–6 parts, in order: leaf parts, `row` or `spacer` |

| Part `kind` | Fields | Rendering |
| --- | --- | --- |
| `text` | `text` ≤60, optional `icon` | Body line(s) under a rule |
| `event` | `time` ≤8, `text` ≤48, optional `icon` | Bold time above the text |
| `metric` | `value` ≤5, `text` ≤24, optional `icon` | 28px figure above a label |
| `list` | 1–3 `items` ≤24 | Bulleted lines |
| `badge` | `text` ≤12 | Outlined uppercase tag, e.g. "Day off" |
| `range` | `low`, `high`, optional `level` 0–3 | `low–high` and the block's optional `unit` (≤4) above a bar; all range parts in a block share one scale |

Schema lengths are maxima. What fits depends on the column count, so `src/validate-v2.mjs` checks each column against `src/design/columns.json`. A column's content is `732 / n − 21` px wide. Body lines fit that width ÷ 11 characters (2 columns: 31, 5: 12, 8: 6) with whole words wrapping, and an inline icon takes about 3 characters. Labels, values, metric values, badges and range text are checked against their own glyph widths. The header and each part's estimated height are summed and must stay within 205px in `weekahead` or 305px in `board`. Errors name the column and what overflowed.

### Layout inside columns

A column is a vertical flex stack. Two layout parts arrange leaf parts without exposing CSS:

| Part | Fields | Behavior |
| --- | --- | --- |
| `row` | `items`: one or more leaf parts; optional `justify` `equal` (default, equal widths), `between`, `start` or `end` (natural widths); optional `align` `top` (default), `center` or `baseline` | Places its items side by side under one rule with an 8px gap. Rows do not wrap and never contain rows or spacers. |
| `spacer` | none | Absorbs leftover height, so the parts after it sink to the column's bottom. Several spacers share the space. |

There is no limit on row items. Each item is checked at its share of the column, `(width − 8 × (k − 1)) / k`, whatever `justify` is, so a row that is too crowded fails on its narrowest content. A row's height is its tallest item; `baseline` rows add 10px because items drop to meet a metric figure's baseline. Spacers and `align` cost no height.

## Required render checks

From the repository root, run `npm ci` if dependencies are missing, then `node tests/design.mjs`. Google Chrome must be installed at the standard macOS path used by that script.

For each gallery screen, use case, and calendar, chart, inline-icon and column stress case, the check:

1. Validates its payload.
2. Renders the actual combined installed template at 800×480 using the included TRMNL framework assets.
3. Inspects computed styles on every element with direct visible text: size must be at least 16px, text at 16px must have weight at least 600, and color must be pure black or white.
4. Serves weather icon URLs from `vendor/weather-icons/`, asserts every icon loads and renders and every vendored icon is reachable from a condition, and that no `.dui-footer` exists.
5. Checks each content section for horizontal and vertical overflow.
6. Saves a PNG, portable HTML preview, and `artifacts/design/render-results.json`.

Run `npm test` for the build, legacy layouts, payload validation, and the v2 design checks. Use TRMNL `startPreview`/`getPreview` after installing changes to verify its server renderer and target device model. A local gallery check does not certify every possible payload or physical device readability; new content that wraps differently should be previewed too.

## MCP-discoverable contract

The installed Full markup begins with `AGENT_DYNAMIC_UI_CONTRACT/1` in a Liquid comment. An authorized MCP client can call `readMarkup` with `plugin_setting_id: "522048"`, `size: "markup_full"` to retrieve the minified v2 JSON Schema, composition constraints, design tokens, validation limits, legacy rules, and update/preview procedure. The comment is absent from rendered output. `scripts/build.mjs` regenerates it from the schema, tokens, and exported composition definitions; `dist/AI-CONTRACT.liquid` is the generated copy. The local render scripts are described but are not exposed as executable MCP tools.
